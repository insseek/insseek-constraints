# 通用约束文档库（insseek-constraints-docs）

> 这里放**与任何具体项目无关**的文档：约束（规定怎么做）、约束模板（怎么写项目的约束）、机制说明（解释为什么成立）。
>
> **本目录是「母版」**：作者手里的一份，供**开新项目时整目录复制一份**过去。
>
> **本库目的**：降本增效、确保安全、提高工作质量；冲突时 安全 > 质量 > 成本。

**本库的三条标准**：

```
① 不依赖具体项目
② 不依赖具体机器、账户配置、preset 与插件安装
③ 不手抄机制数字——只写不随环境变化的做法
```

> 三条标准针对**跨宿主**的约束与模板；`dsh-` 差异表是宿主专属补充，不在此列。
> 说明性文档记录某台机器的实测，只解释「为什么」，不作规范。
>
> 库内带 `dsh-` 前缀的文档**用于 DeepSeek Harness（DSH）**；不带前缀的与宿主无关。
> 约束与模板换机器、换账户、换界面也不失效；说明性文档的数字只作示例。

**选哪份**：

```
· 人：读 `human-agent-collaboration-constraints.md`（最低限度三条；需要时看任务书模板；DSH 用户看附录 C）
  贴团队文档（README / CONTRIBUTING / 内部 wiki），不进 `AGENTS.md` / `CLAUDE.md`
· Agent：读 `agent-collaboration-constraints.md` 的「十行摘要 + 安全三条」，放 `AGENTS.md` / `CLAUDE.md`；
  DSH 再读 `dsh-agent-deltas.md`
· 项目模板 / 机制说明：见下表
```

**两个入口不要混放**：人 → 团队文档；Agent 侧 → 项目指令文件。

**说明性文档（本库内，不作约束引用）**：

| 文档 | 性质 | 与本文库的关系 |
|---|---|---|
| 《DeepSeek Harness 工作机制》（`dsh-working-mechanism.md`） | **说明性** | 「为什么这些对策成立」的机制说明：循环、接缝、压缩公式、工具来源。**具体数字是某台机器的实测**，随安装与配置变化；不得当约束引用 |

**性质三分的含义**（决定了它们能不能当「约束」）：

```
说明性文档  描述「是什么」——把它的内容当成项目规矩是误用
约束性文档  规定「必须怎么做」——可被项目引用为规范
模板        规定「怎么写项目的约束」——只在新项目落地时使用
```

## 在某个项目里使用（四步）

```
第 1 步  把本目录**整体复制**一份到项目根：<项目>/insseek-constraints-docs/
           · 让 clone 项目的人自足读到
           · 原样保留目录名，便于跨项目对照；不要拆散成零散文件
           · 项目 docs/ 里**不放**这些文档的副本（单一来源就是项目根那个同名目录）

第 2 步  按 `agent-collaboration-constraints-project-custom-template.md` 填一份
           项目自己的《自定义内容》，文件名去掉 -template：
           `agent-collaboration-constraints-project-custom.md`，**放在库目录里**
           · 六个编号章节（一 四类浪费：本项目实例 / 二 本项目特有约定 / 三 反例清单 /
             四 已固化的工具 / 五 度量基线 / 六 变更记录）
           · 写项目自己的事实与约定，不重复通用原则，不手抄机制性数字
           · 模板本身也随库留着——它只作**结构基准**，供项目自检比对章节

第 3 步  项目自检加**一条**：项目《自定义内容》的章节结构与库内模板一致
           （不要校验「与母版逐字一致」——那会让项目依赖一个项目外的目录）

第 4 步  在项目的文档索引里登记这份《自定义内容》，并标明性质
           · 通用文档由目录名自明，不必逐份登记
```

**加载成本**：项目入口只写硬约束摘要（十行以内；约束文档开头已给一份可直接用），
全文按需查阅；把整份文档放进固定前缀，等于每一步都为它付费。

**校验什么、不校验什么**（这条是整套设计的关键）：

```
✓ 校验结构（章节标题集合与顺序）—— 保证跨项目可对照、可自动检查
✗ 不校验内容（各节正文）        —— 正文由项目自由填写
✗ 不校验「与母版一致」          —— 项目不依赖本母版，这条本就无法成立
```

## 维护约定

```
· 本库是**唯一来源**：要改内容，改这里
· 改完之后**不自动同步**到各项目——何时同步、同步到哪个项目由作者决定；
  Agent 与工具不得擅自去改各项目里已复制的副本
· 作者原文三份（代码规范 / 写作与审核原则 / 道德规范）**不改写**，只作搬运与复制
· 环境相关事实**不写进正文**：工具清单、阈值、版本、窗口、路径、
  界面位置、社区插件行为——换台机器、换个账户就不成立
  （需要解释时引用机制文档，不要手抄）
· 涉及具体能力的条目写成条件句（「若提供……」）；不做可用性承诺
· 人的约束只写 `human-agent-collaboration-constraints.md`；Agent 侧只写
  `agent-collaboration-constraints.md`；DSH 差异只写 `dsh-agent-deltas.md`
· 通用 Agent 侧是唯一来源：改通用先改 agent；DSH 差异版只补差异，不重复通用规则
· 人与 Agent 互不引用具体条目，只做「见」的指路
· 人的入口=团队文档；Agent 侧入口=项目指令文件；两边不混放
· 命名：与宿主相关的文档加 `dsh-` 前缀，与宿主无关的不加；
  改名时同步本表与文内引用
· 新增或修改库内文档时，请同步本表（名称、性质、用途）
· 库内不出现具体项目的业务内容（项目自己的东西写在该项目的自定义内容里）
```
